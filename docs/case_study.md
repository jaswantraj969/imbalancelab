### Key caveat: duplicated rows

The profile found **3334 rows that exactly duplicate an earlier row** (out of 11183). After the split, **632 of 2237 test rows** (2 of them positive) have feature values identical to an outer-train row, and every CV fold has the same issue (see the split warnings below). The tool reports this as a warning, not proof of leakage: repeated measurements may be genuine in this data. But a model can score such rows partly by memorisation, which could make scores optimistic. The check below tests whether that happened here.

Sensitivity check (post hoc, re-slicing the *stored* test predictions only, with no refit and no re-scoring; nothing was selected from it):

## Data profile warnings (heuristic, not proof)

- `exact_duplicates`: 3334 row(s) duplicate an earlier row; duplicates crossing split boundaries can inflate scores.
- `conflicting_duplicates`: 1 group(s) of rows have identical features but different labels (possible label noise).
- Split check `cross_boundary_duplicates`: 632 test row(s) exactly duplicate outer-train feature rows, and 15 CV fold(s) have validation rows duplicating their training rows (max 581). Scores on duplicated rows may be optimistic.

## Limitations

- One dataset and one outer split. The test numbers are a single draw with no spread.
- Exact duplicate rows cross the train/test and CV boundaries (see the key caveat). Duplicate-aware (grouped) splitting was not used in this pre-specified protocol.
- The test set has 52 positives, so test metrics are noisy.
- Fixed small model configs with no hyperparameter search (by design in the MVP).
- The features are anonymised numeric measurements, so no domain review of leakage was possible beyond the automated heuristics.
- Probabilities are not calibrated.
